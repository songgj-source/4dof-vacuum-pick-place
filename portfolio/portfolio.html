1프로젝트 소개

책상 위 물체 세 종류를 카메라로 찾고, 진공흡착 로봇팔로 집어 3칸 트레이의 정해진 칸에 넣는 시스템입니다. 칸은 기본 규칙(흰 상자 1번, 빨간 정육면체 2번, 줄자 3번)을 따르고, "빨간 상자 3번 칸에 넣어줘"처럼 명령으로 지정하면 명령을 우선합니다. 트레이는 매번 다른 위치에 놓을 수 있어서, 사이클마다 새로 촬영해 물체와 칸의 위치를 다시 계산합니다.

한 사이클의 프로세스 구성

메뉴(sort_menu.py)가 실행기(run_sort.py)를 부릅니다. 실행기는 매 시도마다 ① 계획기(plan_sort.py)로 카메라만 읽어 작업 파일을 만들고 ② 집기·놓기(pick_auto.py)를 실행합니다. 서보 버스와 펌프를 모두 닫은 뒤 ③ HOME 복귀(return_home.py)를 별도 프로세스로 실행합니다. 집기 후 흡착이 확인되지 않으면 종료 코드 3으로 끝나고, 실행기가 처음부터 다시 시도합니다. 그 밖의 실패는 재시도하지 않고 멈춥니다.

장치를 여는 프로세스와 계산만 하는 모듈을 분리했습니다. 인식·좌표·계획 모듈은 하드웨어를 import하지 않아서, 로봇 없이 저장된 영상으로 시험할 수 있습니다.

펌프 제어기 교체: ESP32 펌웨어 새로 작성 (2026-10-16)

ESP32를 새 보드로 바꾼 뒤 기존 펌프 프로그램이 동작하지 않았습니다. 기존 플래시를 백업(SHA256 기록)한 뒤, PC 쪽 Python이 기대하는 p/d/s 프로토콜과 흡착 응답에 맞춰 펌웨어를 새로 작성·업로드했습니다(해시 검증 통과). 식별·흡착·정지 응답과 실제 펌프 구동을 확인했고, 부팅 시 출력 LOW, 배기 300 ms 후 자동 정지로 만들었습니다.

4소프트웨어

① 물체 인식

깊이 영상에서 책상 평면을 맞추고, 평면 위로 솟은 덩어리를 물체 후보로 찾습니다. 덩어리 안의 색 비율로 빨간 정육면체·줄자(노랑)·흰 상자를 구분하고, 어느 쪽에도 충분히 맞지 않으면 추측하지 않고 unknown으로 둡니다. 깊이와 색 영상의 정합 오차 때문에 깊이 중심이 색 영상보다 일정하게 (+17, +5.5) px 치우쳐서, 그만큼 빼서 씁니다.

트레이는 벽(55 mm)과 칸막이를 깊이 높이로 찾습니다. 칸 번호는 손글씨 숫자를 읽어 정합니다. 해상도가 낮아(획 1–3 px) 글자 모양 비교로는 2와 3이 뒤바뀌어서, 회전에 영향을 받지 않는 구조 특징을 씁니다. 곧은 획 하나면 1, 가운데 분기점이 있으면 3, 둘 다 아니면 2입니다. 세 칸이 서로 다른 1·2·3이 아니면 읽기를 거부합니다. 칸에 물체가 들어가 바닥이 가려질 때를 대비해 빈 트레이 프레임을 저장해 두고, 트레이가 밀리면 모서리 정합으로 회전·이동량을 구해 저장한 칸 위치를 옮겨 씁니다.

② 좌표 변환

물체 윗면 중심 픽셀을 카메라 내부 파라미터로 광선으로 바꾸고, 물체 윗면 높이의 평면과 만나는 점을 로봇 base 좌표 (x, y)로 씁니다. 카메라 외부 파라미터(자세)는 팔을 자로 써서 맞췄습니다. 팔을 70 mm 높이로 8곳에 띄우고, 정기구학(FK)으로 계산한 흡착컵 위치에 상자를 놓은 뒤, 팔을 HOME으로 치우고 촬영했습니다. 상자 픽셀과 FK 좌표 8쌍으로 자세만 맞췄습니다(내부 파라미터 고정). 접촉 높이 z는 자로 잰 물체 높이에 흡착컵 보정값(−3.5 mm)과 밀착용 추가 누름(3 mm)을 반영해 정합니다.

③ 역기구학

base가 돌고 나머지 세 축(shoulder·elbow·wrist_flex)은 같은 수직 평면에서 움직이므로, 공구 각도 φ를 정하면 해석해로 풀 수 있습니다.

  • base = atan2(y, x), r = √(x²+y²)
  • 손목 중심: dr = r − r₀ − L₃cosφ, dz = z − h₀ − L₃sinφ
  • cos θ₂ = (dr² + dz² − L₁² − L₂²) / (2L₁L₂)
  • θ₁ = atan2(dz, dr) − atan2(L₂sinθ₂, L₁+L₂cosθ₂), θ₃ = φ − θ₁ − θ₂

L₂ 팔꿈치–손목132.6 mm
L₃ 손목–흡착 끝102.0 mm
r₀, h₀ 어깨 위치27 mm, 160 mm
FK 잔차 RMS (맞춤 전 → 후)5.97 → 1.28 mm

두 해(팔꿈치 위·아래) 중 관절 한계 안의 해만 남기고, 경로를 샘플링해 링크 높이가 책상과 물체 위에 있는지 검사합니다. 관절 영점과 링크 길이는 8개 자세의 실측으로 다시 맞췄습니다.

5문제 해결

실물 시험마다 서보 피드백(목표·실제 위치, 매 틱)과 단계별 결과를 파일로 남기고, 문제가 생기면 이 기록과 코드를 대조해 원인을 확인한 다음 고쳤습니다. 한 번에 한 변수만 바꿨고, 실물로 확인하지 못한 변경은 따로 표시했습니다.

5-1. 좌표 오차: 먼 위치일수록 옆으로 어긋나는 집기 실물 확인

문제
로봇에서 먼 물체일수록 흡착컵이 윗면 중앙에서 옆으로 벗어났습니다. 흡착 순간의 손목 사진으로 10곳을 재 보니 가까운 곳은 약 2 mm였고, 0.26 m 이상에서는 10–16.5 mm였습니다.
분석
오차가 위치에 따라 1차식으로 늘어났습니다(1차식 잔차 RMS 1.8 mm). 무작위 오차가 아니라 카메라 좌표와 팔 모델 사이의 계통 오차라는 뜻입니다. 이후 카메라를 앞으로 3.8 cm 옮기고 방향도 틀면서 기존 보정이 모두 맞지 않게 됐습니다. 눈대중과 자 실측만으로는 카메라 위치를 정확히 잴 수 없었습니다.
수정
팔의 FK 좌표를 기준 삼아 카메라 자세를 8점으로 다시 맞췄습니다(맞춤 RMS 3.0 mm, 교차검증 RMS 6.2 mm, 최대 8.2 mm). 팔 base 영점은 호버 시험으로 2145 → 2104 pulse로 고쳤습니다. 관절 영점과 링크 길이도 8개 자세로 다시 맞춰 FK 잔차를 5.97 → 1.28 mm로 줄였습니다. 옛 카메라 기준 보정값은 서로 겹치지 않도록 0으로 끄고, 원래 값은 되돌릴 수 있게 따로 보관했습니다.
검증
재보정 후 실제 집기에서 흡착컵이 상자 중앙에 닿는 것을 확인했습니다. 10-20 시행 5회의 하강 중 보정량은 1.5–2.4 mm였습니다. 앞뒤 방향 보정량은 실험으로 정했습니다. 0 mm에서는 6 mm 짧아도 성공했고, +10 mm에서는 6.5 mm 넘어가 실패했으며, +5 mm에서는 오차가 0.1 px로 성공했습니다.

5-2. 카메라 재보정 시 기존 위치 보정의 중복 적용 방지 실물 확인

문제
카메라로 계산한 목표와 실제 흡착 위치 사이에 작업 위치에 따라 달라지는 편차가 있어, 경험적 위치 보정 두 가지를 쓰고 있었습니다. 하나는 성공한 집기 위치로 맞춘 앵커 XY 오프셋이고, 다른 하나는 위치별 접선 방향 보정입니다. 카메라를 다시 보정한 뒤에도 이 값이 남아 있으면, 새 좌표에 옛 카메라 기준 보정이 한 번 더 더해집니다.
분석
좌표 계산을 세 단계로 나눠 각 단계가 어떤 오차를 맡는지 정리했습니다. 카메라 자세 추정, 물체 윗면 평면으로의 투영, 경험적 XY 보정입니다. 두 경험적 보정은 옛 카메라 자세의 오차를 메우던 값이라, 자세를 새로 추정하면 근거가 사라집니다.
수정
카메라 내부 파라미터는 고정하고, 로봇 호버 위치(FK)와 영상 픽셀 8쌍으로 카메라 자세만 다시 추정했습니다. 앵커 XY 오프셋은 0으로 맞추고(접촉 높이는 유지), 접선 방향 보정은 gain을 −0.74에서 0으로 바꿔 껐습니다. 원래 값은 같은 파일에 함께 남겨 되돌릴 수 있게 했습니다.
검증
보정 기록에는 8개 대응점의 맞춤 RMS 3.0 mm, 교차검증 RMS 6.2 mm가 남아 있습니다. 재보정 후 실제 집기에서 흡착컵이 상자 중앙에 닿는 것을 확인했습니다. 기준 좌표가 로봇 FK에서 나왔으므로 이 수치를 독립적인 실측 집기 정확도로 해석하지 않았습니다.

5-3. 모터 떨림 운반 떨림 실물 해소 접근 떨림 일부 남음

문제
물체를 들고 운반할 때 팔이 약 6 Hz로 떨렸고, 접근 구간에서도 약 7 Hz의 흔들림이 기록됐습니다.
분석
운반 떨림은 base가 느리게 돌 때 가장 컸습니다. 직선(현) 경로는 중간에 반경이 줄었다 늘어서 base 각속도가 들쭉날쭉했고, 저속에서 stick-slip이 생겼습니다. 여기에 시험용으로 올려 둔 base 임시 게인 P32가 겹쳤습니다. 접근 떨림은 P48을 지정한 실행에서 어깨 추종 오차의 고주파 성분 RMS가 1.87 pulse(7.1 Hz)였습니다.
수정
base 게인을 기본값 P16으로 되돌리고, 운반 경로를 base 기준 극좌표 보간으로 바꿔 base가 일정 속도로 돌게 했습니다. 접근은 P32로 낮추고 명령 주기를 13.4 ms 틱(300 pulse/s)으로 맞췄습니다.
검증
운반 떨림은 실물에서 해소된 것을 확인했습니다. 접근은 P만 바꾼 비교에서 0.42 pulse로 줄었지만, 다음 반복에서 1.25로 변동해 완전히 해결했다고 판단하지 않았습니다. 같은 조건에서 300 pulse/s(13.4 ms 틱)는 어깨 RMS 0.46–0.52로 4회 모두 보정 없이 5 mm 안에 도착했고, 150 pulse/s(26.7 ms 틱)는 1.34–1.47이었습니다.

5-4. 하중이 걸린 서보 관절의 정지 상태 인계 개선 모의 시험 검증

문제
로봇팔이 정지해 있는데도 다음 동작으로 넘어가는 제어 인계가 거부됐습니다. 하중 때문에 목표와 실제 위치 사이에 3–6 pulse의 일정한 편차가 남는 상태를, 아직 움직이거나 안정되지 않은 상태와 구분하지 못했습니다.
분석
기존 정지 처리는 현재 위치를 새 목표로 다시 써서 붙잡았습니다. 하중이 걸린 관절은 새 목표에서도 다시 밀려나 2 pulse 기준을 넘었습니다(예: 팔꿈치 목표 2024, 실제 2028). 또 하중 보상 hold는 3 pulse 편차를 성공으로 보는데, 정지 확인과 다음 경로의 사전 검사는 2 pulse를 요구해서 두 기준이 서로 맞지 않았습니다.
수정
목표를 덮어쓰지 않고, 기존 목표가 그대로인지와 여러 표본(3회)에서 실제 위치가 안정적인지를 함께 검사합니다. 편차가 3–6 pulse로 일정하면 관절별 하중 보상 오프셋으로 기록하고, 이후 목표 일치 검사에서도 같은 오프셋을 씁니다. 허용 오차를 넓히는 대신 목표 불변, 위치 변화, 편차 크기를 따로 검사합니다.
검증
모의 서보 시험으로 검증했습니다. 실물 재시험은 이 분기에 들어가기 전 단계에서 멈춰, 실제 효과는 아직 확인하지 못했습니다. 보상은 관절 영점 보정이나 TCP 정확도 개선이 아니라 정지 판정의 일관성을 위한 것입니다.

5-5. 트레이 방향 오인으로 물체가 칸 벽에 걸림 수정 후 실물 성공

문제
정육면체를 2번 칸에 놓을 때 칸 벽에 닿아 떨어졌습니다.
분석
깊이 영상에 트레이 위쪽 1/3의 벽 조각만 보였고, 조각이 거의 정사각형이었습니다. 그래서 조각의 주성분 방향(PCA)으로 구한 트레이 긴 축이 실제보다 12° 틀어졌습니다(164.7° vs 약 177°). 칸 2 중심이 칸 왼쪽 벽 옆으로 계산됐고, 칸 간격도 86/95 mm로 불균형했습니다.
수정
색 영상에서 판지 실루엣(길이:폭 2.4)의 긴 축을 구합니다. 벽 조각이 길쭉하고 실루엣과 15° 이내일 때만 기존 방식을 그대로 쓰고, 둘 다 애매하면 방향을 추측하지 않고 거부합니다.
검증
같은 사진에서 칸 2 중심이 칸 한가운데로 옮겨졌습니다. 트레이 위치를 바꾼 뒤 흰 상자 → 1번 칸, 정육면체 → 2번 칸 실물 시험에 성공했습니다.

5-6. 물체가 놓인 뒤 트레이 칸을 인식하지 못하는 문제 대응 실물 프레임 확인

문제
빈 트레이에서는 칸 바닥 3개를 찾을 수 있지만, 물체를 하나씩 넣으면 바닥이 가려져 다음 작업의 칸 위치 계산이 거부됐습니다. 기울어져 들어간 흰 상자나 칸을 가로지른 케이블도 같은 문제를 만들었습니다.
분석
칸 위치를 구하는 일(트레이 구조)과 칸 안에 무엇이 있는지 보는 일이 한 영상에 묶여 있어서, 가림이 생기면 구조 추정까지 실패했습니다.
수정
빈 트레이의 RGB·깊이 프레임을 기준으로 저장하고, 이후에는 기준 영상과 현재 영상의 트레이 바깥 모서리 3곳을 템플릿 정합으로 비교합니다. 모서리는 칸 안의 물체에 가려지지 않습니다. 트레이가 조금 밀리거나 돌았으면, 정확히 맞는 모서리 2곳 이상으로 영상 평면의 회전·평행이동을 구해 저장한 칸 위치를 옮깁니다. 이동 40 px나 회전 6°를 넘거나 맞는 모서리가 2곳 미만이면 저장 좌표를 쓰지 않고 카메라 재인식으로 돌아갑니다.
검증
실제 프레임에서 9 px 이동과 −1.3° 회전을 잔차 0.3 px로 측정했고, 옮긴 칸 중심이 실제 칸 한가운데에 놓였습니다. 합성 회전 2–3°에서는 오차 약 1–2 px였습니다. 영상 평면 정합이라 트레이 높이 변화나 큰 기울기는 보장하지 않고, 반복 성공률은 별도 시험이 필요합니다.

5-7. 4축 로봇팔의 자세 제약을 고려한 집기·운반 경로 계획 실물 사용

문제
4축 팔은 손목 회전 자유도가 하나뿐이라, 흡착컵을 수직으로 유지하면 닿지 않는 위치가 있었습니다. 최종 목표점에 닿는다고 해서 운반 중간 경로를 실행할 수 있다는 보장도 없었습니다.
분석
목표 좌표만으로는 실행할 수 있는지 알 수 없어서, 자세와 경로 조건까지 포함해 실행 가능성을 판단하는 문제로 바꿨습니다.
수정
집기는 120 mm 접근, 70 mm 호버, 접촉 세 지점을 같은 기구학 모델로 검사합니다. 위치 오차를 고려해 반경 8 mm 여유를 둡니다. 수직으로 닿지 않으면 공구 기울기를 0–20°에서 5° 단위로 늘려 가장 작은 값을 고릅니다. 운반은 물체 높이, 트레이 벽(55 mm), 주변 물체의 높이·반경으로 이동 높이와 충돌 여유를 정하고 상승·기울이기·수평 이동·하강·후퇴로 구성합니다. 각 구간은 10 mm 간격으로 도달 가능성을 검사합니다. 놓기 기울기는 최대 50°까지 같은 방식으로 탐색합니다.
검증
실제 시행에서 흰 상자는 1번 칸 벽을 피하려고 45° 기울여 놓았고, 먼 물체는 기울인 집기로 집었습니다. 범위 밖 목표(예: 반경 0.157 m의 줄자)는 계획 단계에서 거부됐습니다. 검사는 기구학과 단순화한 높이·원통 모델에 기반하므로, 정밀 CAD를 이용한 전체 충돌 검증과는 다릅니다.

7한계와 개선

인식의 한계

  • 색 비율로 분류하므로 밝은 무채색 물체는 흰 상자와 구분하지 못합니다. 조명이 바뀌면 기준을 다시 맞춰야 합니다.
  • 손글씨 숫자 인식은 지금 필체(검은 펜, 3의 가운데가 뾰족하게 만나는 모양)에서만 확인했습니다.
  • 트레이 벽이 잘 보이지 않으면 칸 바닥 방식으로 넘어가는데, 이때 칸 중심 불확실도가 최대 약 25 mm입니다.

흡착의 한계

  • 압력 센서가 없어 흡착을 직접 확인하지 못합니다. 손목 사진 판정은 한 조명·한 책상에서 맞춘 잠정 기준이고, 흰 상자에서 오판했습니다.
  • 흡착은 흡착 명령 뒤 정지·배기 명령이나 리셋 전까지 유지됩니다. 통신이 끊겨도 자동으로 멈추지 않으므로, 운반 중 USB가 재연결되면 물체가 떨어질 수 있습니다.
  • 윗면이 평평한 정육면체에서만 흡착 성능을 확인했습니다. 흰 상자와 줄자는 실물로 옮겼지만, 접촉 높이 보정값은 정육면체 기준을 그대로 가정했습니다.

작업 범위

  • 집기 반경은 약 0.16–0.30 m입니다. 범위 밖의 물체나 칸은 계획 단계에서 거부합니다.
  • 먼 물체는 공구를 최대 20° 기울여 집습니다. 기울인 집기는 수직 집기보다 도착 허용 오차가 큽니다(8 mm).

다음 개선 방향

  1. 압력 센서 추가: 흡착 라인에 진공 센서를 달아 사진 판정을 대체하고, 흡착 실패를 들기 전에 감지합니다.
  2. 통신 단절 시 안전 동작: ESP32 펌웨어에 heartbeat를 넣어 통신이 끊기면 정해진 동작을 하게 합니다.
  3. 외부 기준 정확도 측정: 격자 판 위에서 흡착컵 끝 위치를 직접 재어 FK·카메라 기반 지표를 검증합니다.
  4. 인식 강건화: 색 규칙 대신 소량 데이터로 학습한 분류기를 쓰고, 조명 변화 시험 세트를 만듭니다.
  5. 정지 제어와 이동 제어 분리: 이동 중 게인과 도착 후 보상 hold의 기준을 하나로 정리해, 정지 인계 실패를 줄입니다.
